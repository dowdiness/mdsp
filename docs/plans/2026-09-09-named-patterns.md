# 名前付きパターンとグループ化

## 目的と構文

同じフレーズを複数セクションにコピーせず、一か所の編集を全使用箇所へ反映する。
パターンは時間に対する問い合わせとして再利用し、参照自体は時計・発音・再生位置を持たない。

```js
let motif = note("E4 G4 A4").slow(3);
let kick = s("bd").gain(0.46);
let groove = stack(motif, kick);
song(
  section("intro", 12, motif),
  section("main", 24, groove),
  part("a", "intro"),
  part("b", "main")
)
```

- `let name = expression;` を最終式の前に置く。セミコロンは必須。
- 名前は英字または `_` で始まり、以降は英数字と `_`。組み込みの
  `let`, `s`, `note`, `chord`, `stack`, `song` は定義名に使えない。
- 定義は上から順に有効となる不変値。同名の再定義、未定義参照、前方参照を拒否する。
  自己参照と相互参照も、まだ有効でない名前の参照として拒否する。
- 名前は通常の式なので、`stack(...)` の引数、メソッドの対象、sectionの本文で使える。
  `groove.gain(0.2)` はその使用箇所に適用され、元の定義を変更しない。
- 定義はパターン・song両モードと、パターンモードの `$:` 行で使用できる。
  名前の有効範囲は一つの入力だけで、次の解析へ持ち越さない。
- 定義そのものは演奏しない。最終式から使用するパターンだけが鳴る。
  未使用の定義も検証する。

## 実装境界

既存miniパーサーが入力ごとに局所的な環境を作り、定義を準備時に解決する。
文字列置換や実行時の名前検索は使用しない。グループは既存のstackと同じパターン値であり、
別の再生器や音源を持たない。パターンの周期とセクションの時間規則をそのまま保つ。

通常画面は既存のprepare/applyを呼ぶ。定義の変更でも継続適用の配置・テンポ条件は同じ。
解析エラーは準備を失敗させ、適用済み・受理済みの演奏を変更しない。

文書APIのPatternDocは一意のノードIDを要求するため、名前の各使用箇所を独立した
opaque pattern leafとして表現する。定義内の個々のノードを使用先へ複製したり、
文書APIをDAGへ変更したりしない。したがって名前の使用箇所より内側の細粒度の
出典追跡・文書編集はこの実装では提供しない。定義編集後に古いlowering cacheの値が
残らないことは、MiniAuthoringPipeline経由で検証する。

## 完成条件と検証

- 名前付き式とインライン式の発音区間・値が一致する。
- 同じ定義を複数回使っても、使用箇所の変形が他へ漏れない。
- 一つの定義の変更が複数セクションへ反映され、配置を変えない。
- 重複、未定義、自己参照・相互参照、予約名、区切り欠落を各解析入口で拒否する。
- 実AudioWorkletで定義を変更し、継続適用と失敗時の適用済み曲の保持を確認する。
- [光の軌道](../../examples/light-orbit.mini)は元の12セクション・240 cyclesの曲と
  半cycle単位の全イベント比較を行う。曲末尾の次の2 cyclesも比較する。
  比較は構文整理による意味の保存を検証するもので、聴感や出力遅延の評価ではない。

小節構文、量子化更新、ゲーム向け遷移、エフェクト、Worker移行は範囲外。

検証結果: 全3ターゲット各1,078件、通常画面30件、ブラウザ26件が成功。
詳細は[検証記録](../performance/2026-09-09-named-patterns.md)を参照。

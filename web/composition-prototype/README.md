# 共有定義による作曲準備の試作

パターンの式を一か所で編集し、参照するセクションへ反映するための開発用試作です。`examples/light-orbit/named.json` はパターン、参照の組合せ、曲順を分けます。小節・拍は配置の表記であり、フレーズ周期を小節の倍数に制限しません。

## 検証

MoonBitと依存パッケージを導入し、`npm run verify:composition-authoring` を実行します。既存構文の「光の軌道」と全曲イベントが一致すること、定義の変更・配置・長さ・ランダムな音抜きに対して差分準備が全体再準備と一致すること、最新編集と取消しの競合を検証します。結果は `artifacts/composition-prototype/definition-check.json` です。

## 境界

`named.mjs` は名前を既存構文へ展開します。式をJavaScriptとしてevalしません。`prepare.mjs` は明示的に渡されたコンパイラを使い、有限イベント列と次のキャッシュを返します。`worker.mjs` がコンパイラとキャッシュの寿命を所有し、`preparation-queue.mjs` は実行中1件と最新待機1件に制限します。取消しは結果を無効にしますが、実行中のコンパイル自体を中断しません。

120 BPM、4/4、48kHz、128フレーム、最大256拍に限定します。定義と問い合わせ範囲が同じ場合だけ結果を再利用します。全曲イベント列の再構築と転送は毎回必要です。`prepare` は全体再準備の比較基準、`prepareIncremental` はScene単位の比較基準、`prepareDefinitions` がWorkerで使用する方式です。

## 再生と編集

`npm run prototype:composition` で配信し、http://127.0.0.1:8770/web/composition-prototype/ を開きます。ポートは `COMPOSITION_PORT` で指定できます。`npm run prototype:composition-cli` は同じ状態遷移を端末で操作します。

共有定義の変更を準備してから次の小節で適用します。ゲーム入力のcalm／combatはsuspension／confluenceの先頭へ移動して繰り返します。曲順へ戻る際はセクションと拍位置を指定します。既に鳴っている音と共有delayを保持します。新しい音にだけ編集を反映します。準備中と予約中の取消しができ、音声側の小節境界の1ブロック前以降は予約の変更を拒否します。クリック直後の小節に間に合う保証ではありません。

`model.mjs` が明示的な状態と操作から次の状態とイベントを返し、`processor.mjs` が通信、時計、DSPと残響の寿命を所有します。音声時計が不連続になった場合は保留し、明示的に再開します。

`npm run verify:composition` は全曲一致、共有定義の影響先、編集とゲーム入力の合成、取消し、古いrevision、ループ境界を検証します。ブラウザを開いて `scripts/composition-browser.js`、`scripts/composition-ui-check.js`、`scripts/composition-race-browser.js` をPlaywright CLIのrun-codeで実行します。波形照合は `node scripts/composition-browser-verify.mjs`。実行時に取得したキャプチャを参照DSPと照合し、delayをリセットする負の対照も比較します。

## 制限

開発用試作であり製品実装ではありません。JSON形式は最終構文ではなく、編集できるのは定義の式で、演奏中の配置変更は拒否します。全曲・Sceneを準備する有限方式であり、継続的なイベント補充は含みません。各列10000イベント、合計20000イベントを上限とします。音声側にも検証・コピー・イベント抽出の割り当てがあり、無割り当て・実時間性能の保証はありません。途中試聴は過去の発音・残響を再構築しません。共有エフェクトは一次ローパスと固定delayです。

元の統合試作では出力不足を観測しており、原因未特定です。内部PCMの一致と物理出力の安定性は別の検証です。再生品質の保証や音切れ修正はこの試作の完了条件に含めません。

## 分割後の検証結果（2026-09-08）

JSチェック、WASM-GCビルド、全曲イベント比較、通常表示ブラウザ18秒の169イベントと左PCM864000サンプルの参照一致、無効な編集・取消し・最新編集だけの採用を確認しました。[波形照合の集計](../../docs/performance/2026-09-08-composition-pr-playback.json)。全体JSテストは1067件中1063件通過で、graphのプロパティテスト4件は基底の作曲準備ブランチでも同じ名前で失敗します。全体テスト通過とは扱いません。

## 共有フィルターの展開

再生開始時に共有ローパスを有効にします。全パート → ローパス → 共有delayの順で処理します。suspensionの最初の4拍で閉じ、最後の4拍で開きます。静穏／戦闘への切替時は現在値から4拍で600／12000Hzへ動かします。手動の目標Hz・長さ（拍）は現在値から再指定でき、曲の自動展開にも戻せます。

フィルター値はセクション内の時刻から求めるため途中試聴でも再現できます。移動先の値には30msで接続します。過去の発音や残響を復元する意味ではありません。編集や場面切替でフィルター・delayの内部状態をリセットしません。個別パートのエフェクト、リバーブ、任意のエフェクト順序を指定する構文は含みません。

`node scripts/composition-filter-check.mjs` で途中再指定、途中位置、インパルス応答、ブロック分割不変性を確認します。通常表示ブラウザで `scripts/composition-filter-browser.js` を実行し、`node scripts/composition-browser-verify.mjs --filter` で記録波形を照合します。

フィルター追加後の通常表示ブラウザ18秒でも、123イベントと左PCM864000サンプルが参照実行と一致しました。途中試聴の600Hz、変化途中の再指定、編集と場面切替の連続性を確認しました。[照合結果](../../docs/performance/2026-09-08-composition-pr-filter.json)。この1回の出力不足は0ですが、過去の音切れの解消を意味しません。

分割後の共通MoonBitコアのベンチマークは59件すべて通過しました。[測定結果](../../docs/performance/2026-09-08-composition-pr-bench.txt)。ブラウザの出力不足を検証するベンチマークではありません。
